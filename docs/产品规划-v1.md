# 产品规划 v1 · AI 博主的单人内容工厂

> 定位：**你只负责出镜和点击发布，其余全部由本系统承接。**
> 不是"AI 生成视频"，是"在你拍好的素材上做减法，且不能把话说坏"。

## 三、粗剪：核心规则（这是产品最值钱的部分）

### 3.1 为什么输出"保留区间"而不是"删除列表"

两种错误的代价不对称：

- 漏删一句"嗯…那个"→ 片子啰嗦 2 秒，不影响理解
- 误删一个"但是"→ 前后因果断裂，整段逻辑垮掉，且**你在成片里很难听出来**

所以系统只输出"哪些区间留下"，其余全部丢弃。默认不动，只有明确判定可删才切。

### 3.2 白名单删除（只删这几类，其余一律保留）

| 类型 | 判据 | 处理 |
|---|---|---|
| 长静默 | 停顿 > 1.2s | 压到 0.35s |
| 独立语气词 | 「嗯/啊/那个/就是说」单独成段且前后都有停顿 | 整段删 |
| 完全重复 | 相邻两句相似度 > 0.92 | 删后一句 |
| 自我纠正的废弃段 | 「不对，我是说…」 | 只删「不对」及其前的残句 |
| 拍摄指令残留 | 「等一下」「重来」「卡了」 | 整段删 |

### 3.3 保护清单（命中即永不删，即使看起来像废话）

- 转折与因果：但是、所以、因为、然而、不过、其实、换句话说、问题是
- 数字、专有名词、时间点、人名、产品名
- 每段的首句与末句
- 问句（互动钩子）
- 紧跟删除点之后的第一句（常是重述，删了就断了）

### 3.4 硬约束

1. **顺序绝不重排**。只做减法，不做拼接。
2. 每段保留区间两端各留 **0.15s padding**，避免咬字。
3. 只在**句间或停顿处**切，句中断点不动。
4. 相邻两个删除点之间至少保留 **1.5s**，防止碎剪（碎剪比啰嗦更难听）。
5. 总时长缩短超过 **35%** 时告警——大概率切多了，退回人工确认。

### 3.5 你的复核界面（3 分钟）

`切点对照表.md` 形态：

```
| # | 时间码 | 状态 | 原文 | 原因 |
|---|--------|------|------|------|
| 1 | 00:00-00:12 | ✅ 保留 | 今天聊一个反常识的事… | 开场 |
| 2 | 00:12-00:14 | ❌ 删除 | 嗯…那个… | 独立语气词 |
| 3 | 00:14-00:31 | ✅ 保留 | 但是真正的问题是… | 含转折词，保护 |
```

你只需要做一件事：标出"这条删错了，救回来"。

## 四、多机位怎么用

第一版不追求自动切机位，按"主 + 辅"处理：

1. `angles.json` 标注每个文件是主机位还是辅机位，以及起始偏移（若同时开机则为 0）。
2. 粗剪默认全程主机位。
3. 辅机位作为**插入镜头（B-roll）**：ASR 命中关键词（屏幕、这个数、图表、演示）时，在 `plan_rough.json` 里建议插入 2-4 秒辅机位画面，你复核时可删。
4. 时间对齐靠音轨互相关；若两机位都录了声音，优先用音频对齐，比打板可靠。

## 五、剪映精剪 SOP（你的操作手册）

草稿生成后，按这 7 步走。**顺序不要换**，因为后面每一步都依赖前一步的结果。

**第 1 步 · 听接缝（最重要）**
逐个播放每个切点前后 3 秒。听到"话被切断了"就把它拖回 0.5-1 秒。这一步决定片子成不成立，其他都是锦上添花。

**第 2 步 · 修字幕**
粗剪草稿的字幕来自机器转写，必有错别字和断句错误。重点查：人名、产品名、数字、专业术语。改完再做后面的事，否则花字会建在错字上。

**第 3 步 · 加重点花字**
每 20-30 秒最多一个。只给你希望观众记住的那一句。花字多了等于没有重点。

**第 4 步 · BGM 与卡点**
BGM 音量压到 -22dB 左右（人声为主）。切点和音乐重拍对齐时，观感提升最明显——这一步值得多花 10 分钟。

**第 5 步 · 转场（克制）**
只在**场景切换**处用，同一段落内部不要加。硬切本身没问题，滥用转场反而显廉价。

**第 6 步 · 调色 / 滤镜**
全片统一一个滤镜即可。多机位素材色温可能不一致，用"调节"里的色温对齐，比套滤镜更有效。

**第 7 步 · 导出**
1080×1920 / 30fps / 高码率。导出前把播放头拖到全片快速过一遍，专看黑帧和字幕溢出边界。

## 六、发布：草稿箱 + 平台适配器

**不做自动上传**（违反平台协议且账号风控风险大于收益）。做"发布包"，你点上传。

每个平台一个配置文件，加平台 = 加一个 JSON：

```
platforms/
├── x.json
├── douyin.json
├── shipinhao.json
└── xiaohongshu.json
```

配置项：画布尺寸、时长上限、标题字数、话题数量上限、封面比例、文件名规则。

系统产出 `07-发布/<平台>/`：

- `video.mp4`（按该平台规格转码）
- `title.txt` / `desc.txt` / `tags.txt`
- `cover.png`
- `发布清单.md`（含该平台的发布入口链接 + 检查项）

分平台文案不是同一段话复制四遍——X 偏观点钩子，抖音偏前三秒冲突，视频号偏熟人转发语，小红书偏"收藏价值"。

## 七、数据回填与迭代

`metrics.csv` 字段：

```
date,platform,video_id,title,topic_type,angle,duration,views,completion_rate,likes,comments,saves,follows,note
```

- 每周填一次（平台后台抄数），系统算「选题类型 × 平台」的完播中位数
- 迭代规则：某选题类型连续 3 条完播低于中位数 → 降权，下周选题卡减少该类型
- 反哺点：同一选题在 4 个平台的表现差异，决定下一条首发平台
