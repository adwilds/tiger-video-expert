# 操作手册

从「我是谁」到「发出去了」。哪些是系统做的、哪些必须你做，这里分开写清楚。

---

## 你要准备的

| 东西 | 说明 |
|---|---|
| 主机位视频 | 一整条，不要自己剪，卡了重来也留着 |
| 辅机位视频（可选） | 跟主机位同时开机。**它的唯一用途是盖跳切**，不是多角度炫技 |
| 稿子（可选） | 有稿子更好，没稿子就要靠转写判断 |
| 剪映能打开 | 装好剪映，随便新建一个草稿，确认草稿列表能读到东西 |

辅机位没有也能跑，跳点会进 B-roll 待补清单，你后期补空镜。

## 开工之前：三步定方向

下面八步是"已经有选题、有素材"之后的事。**选题从哪来，靠这三步。** 跳过它们，八步做得再顺也是在猜。

### 第一步：写身份卡（只做一次）

```bash
python scripts/pipeline.py profile init
```

在工作区根（不是某一期目录里）生成 `profile.json`，填四项：

| 字段 | 要点 |
|---|---|
| `account` | 账号名 |
| `track` | 赛道关键词，至少 3 个，写你会**长期**做的 |
| `audience` | `who` 要写到职业 + 处境 + 正在为这件事发愁；`pain` 一句话 |
| `goal` | 涨粉 / 带货 / 引流 / 品牌，四选一 |

观众写成"年轻人""上班族"会被**直接拦下**。这不是挑刺——观众说不清，后面每一关都没有靶心。

填完跑：

```bash
python scripts/pipeline.py profile check
```

它校验必填项，并重新生成人读的 `身份卡.md`。**只改 json，不要手改 md**——md 是生成的，下次 check 会把你的手改冲掉。

### 第二步：抓情报

```bash
python scripts/pipeline.py intel fetch 我的第01期 --days 14
```

源清单在 `intel-sources.json`（工作区根）。第一次跑会生成模板，把示例源换成你要跟的，RSS 和 Atom 都吃。
抓回来的东西进 `intel/raw.jsonl`，**跨期累积**，第二期不用重抓。

在别处看到好东西，直接结构化喂进去，别口头转述：

```bash
python scripts/pipeline.py intel add 我的第01期 \
    --title "剪映新版把草稿改成加密" --url "https://..." --source "量子位"
```

抓失败的源会逐条报错并计数。**一条都没抓到就直说"这次没新增"**，不要顺势编选题。

### 第三步：排候选，定选题

```bash
python scripts/pipeline.py intel rank 我的第01期      # 出 00-intel/选题候选.md
python scripts/pipeline.py topic pick 我的第01期 1    # 第 1 条落成选题卡
```

候选表按五项**客观**特征排序：赛道匹配 35%、热度 25%、时效 20%、可验证 10%、可拍 10%。
同一条被多家报道会合并成一条，标「N 个源在说同一件事」。

**分数高只说明值得看一眼，不说明值得做。** 选题卡落出来四栏是空的，这是故意的：
填不满就写"不做"，别硬凑理由。这一条留着，下周不会重想一遍。

填完选题卡，再往下走八步。

## 动手八步

### 第 1 步：建项目

```bash
python scripts/pipeline.py init 我的第01期 --name 第01期
```

会建好目录、写好 `project.json`，并自动找到剪映草稿库的位置。

如果它说"没找到剪映草稿库"，打开剪映新建一个草稿，再把路径抄进 `project.json` 的 `draft_folder`。

先跑一次体检确认环境没问题：

```bash
python scripts/pipeline.py doctor
```

看 `草稿库布局` 这一行：
- `plaintext` —— 老版剪映，直接用
- `info` / `encrypted` —— 新版剪映，系统会自动改写文件名，不用你管

### 第 2 步：放素材

```
我的第01期/02-raw/main.mp4      ← 主机位
我的第01期/02-raw/cut.mp4       ← 辅机位（可选）
```

然后改 `project.json` 告诉系统哪个是哪个：

```json
{ "angles": { "main": "02-raw/main.mp4", "cut": "02-raw/cut.mp4" } }
```

### 第 3 步：转写 + 洗音轨

```bash
python scripts/pipeline.py ingest 我的第01期
```

系统做三件事：抽音轨 → 转写（词级时间戳）→ 降噪 + 响度归一到 -14 LUFS。

**首次会下模型**（约 500MB）。国内先设镜像：

```bash
set HF_ENDPOINT=https://hf-mirror.com
```

CPU 上 `small` 模型大约跑素材时长的 1/4。10 分钟素材等 2-3 分钟。
想更准就把 `project.json` 的 `asr.model` 改成 `medium`，慢一倍。

### 第 4 步：看切点（**最重要的一步**）

```bash
python scripts/pipeline.py cut 我的第01期
```

打开 `04-cut/切点对照表.md`。

**算法只删「明确是废话」的东西**：语气词、重录、自我纠正、拍摄指令。
它不删"但是""所以""其实""问题是"——这些词一删，前后因果就断了，而且成片里听不出来。

你要做的是**扫一遍，标出它删错了的地方**。看到该留的被删了，把那句改成 `manual`：

```json
{ "text": "这句不能删", "keep": true, "manual": true }
```

改完重跑 `cut`，算法不会再动它。

这一步别跳。机器不懂你的语境，跳过就是拿成片赌。

### 第 5 步：出粗剪草稿

```bash
python scripts/pipeline.py build 我的第01期
```

系统在这一步做四件容易做错的事：

1. **画面不留黑帧** —— 切点表里的呼吸停顿折算回源素材，画面首尾相接
2. **音画一起切** —— 音频按同一套保留区间切段，不是挂整条原音轨（否则越到后面越飘）
3. **跳点换机位** —— 每个断开处自动切辅机位，盖住跳切
4. **写对文件名 + 修元信息** —— 否则剪映列表里能看到草稿，点开是空的

跑完去看 `05-plan/B-roll待补清单.md`：还差几处空镜，时间点在哪。

**打开剪映**，草稿列表里应该出现你的项目名。点开看三件事：

- 画面连不连（有没有黑帧）
- 嘴型对不对得上声音
- 字幕在不在

### 第 6 步：精剪（剪映里做，7 步）

粗剪是半成品。下面七件事机器做不了，得你在剪映里过一遍。熟练后整条约 20 分钟。

**① 先只看不动手。** 用 JKL 过一遍，把"别扭"的时间点记下来（空格键暂停，Shift+M 打标记）。不要边看边改，会越改越乱。

**② 修咬字。** 切点已经算好了，这里只修"半个字被切掉"的地方——在音频轨上把片段边缘拖 1-2 帧（≈0.04-0.08s）。修太多就成手动剪了。

**③ 补 B-roll。** 按 `B-roll待补清单.md` 的时间点，在第 5 轨（画中画/贴纸）铺 1-1.5 秒空镜：手部动作、屏幕、白板、街景。**这是整条片子"像不像专业剪的"的分水岭。**

**④ 调音量包络。** 人声保持不动，BGM 压到 -22 到 -26。重点句（钩子、结论）前面 2 帧把 BGM 拉低 3-4dB，说完再抬回来。这一步做完，观众会觉得"声音很干净"，但说不出为什么。

**⑤ 断行。** 字幕一行不超过 16 个中文字。专有名词不拆行——宁可把整行往前挪。竖屏字幕底部留出平台 UI 的位置（安全区下沿约在画面 78% 处）。

**⑥ 封面。** 抖音/小红书要 3:4，X 要 16:9，各出一版。封面上的字要占画面高度的 1/6 以上，小屏才看得清。

**⑦ 导出。** 1080p / 30fps / H.264 / 码率 12-16Mbps。导出后**自己对一遍时间轴**——预览和成片偶尔不一致，这是剪映的老问题。

### 第 7 步：出发布稿

```bash
python scripts/pipeline.py pack 我的第01期
```

第一次跑会生成 `06-publish/post.json` 模板，填好再跑一次。

产出四个平台各一份成稿，加一份 `发布前检查.md`：

```
06-publish/
├── post.json          ← 你填这个
├── douyin.md
├── xhs.md
├── shipinhao.md
├── x.md
└── 发布前检查.md       ← 先看这个
```

每份成稿里已经按平台规则算好：标题字数超没超、话题够不够、时长在不在甜点区间、要不要烧字幕。

**没有一键发布，这是故意的。** 平台端自动发布的失效方式是静默的——账号被限流你不会收到通知。最后那一下点击留给你。

### 第 8 步：数据回填（发完 7 天做，每周一次）

从平台后台抄数字回来，一条命令记一行：

```bash
python scripts/pipeline.py metrics log 我的第01期 --platform douyin \
    --views 12000 --completion 42% --topic-type 反常识 --title "AI 剪辑的门槛不是工具"
```

`--completion` 写 `42%` 或 `0.42` 都行。`--topic-type` 是你自己给的分类（反常识 / 拆解 / 复盘 / 热点），分类越稳定，后面的结论越可用。

每周跑一次汇总：

```bash
python scripts/pipeline.py metrics report --all .
```

它只回答两个问题：

- **这个选题类型还要不要继续做** —— 某类型最近 3 条全部低于此前基线，提示降权；只是建议，减量不是停掉
- **下一条该首发哪个平台** —— 同一条内容在多个平台的完播差异

**样本不满 6 条它不会给结论**，会直接写"判断不了"。这时候照常发，别拿两条数据调方向。

## 随时查看进度

```bash
python scripts/pipeline.py status 我的第01期     # 单个项目
.\run.cmd board                                # 全部项目：双击 老虎AI爆款·内容专家.html
```

工作台是**只读快照**：跑完一步重新生成，看板不会自己刷新。它不联网、不发请求，路径一律相对项目目录，截图分享不会漏出本机目录结构。

会告诉你哪一步做了、哪一步没做、下一步该跑什么。

```
intel/raw.jsonl       情报库，跨期累积
```

## 常见问题

**剪映里看不到草稿？**
先跑 `doctor` 看草稿库路径对不对。路径对的话，检查草稿名有没有被剪映过滤掉（比如带特殊字符）。

**打开草稿报"草稿内容已损坏"？**
剪映 6.0+ 会把草稿加密。本项目不逆向解密，而是按**剪映版本**决定落盘方式：6.0 以上双写明文
`draft_content.json` + `draft_info.json`，剪映打开时原地升级。版本是自动读的，
`run.cmd doctor` 会写出「剪映版本」「布局依据」两行，判错了用 `build --layout info` 或
`--layout plaintext` 手动指定，不用改代码。

还报「草稿内容已损坏」就说明这个版本不再接受明文时间轴：改用剪映自己新建草稿、再把素材拖进去，
或把剪映降到仍接受明文的版本并关掉自动更新。

**草稿写到哪个目录**同样不要靠猜。剪映允许把草稿目录改到别的盘（设置里改过的话，
默认的 `%LOCALAPPDATA%` 路径就是错的，写进去列表里根本不显示）。本项目读剪映的
`Config/globalSetting` 里的 `currentCustomDraftPath` 来定位真实草稿库；
`project.json` 里也可以写 `%JIANYING_DRAFTS%` 这个占位符，运行时按本机配置解析。

**转写全是错的？**
模型太小。`project.json` 里 `asr.model` 改 `medium`。专业术语多的换 `large-v3`（慢但准）。

**切太多了 / 切太少了？**
`project.json` 的 `cut.silence_target` 管停顿压缩目标（默认 0.35 秒）。切太狠就调大到 0.5；切太少就调小。`min_keep_gap` 管"多短的间隙不切开"（默认 1.0 秒）。

**音画对不上？**
跑 `verify` 看报什么。分段音轨正常情况下不会有累计漂移，对不上通常是源素材本身有多音轨或者可变帧率。

**能换个画布比例吗？**
改 `project.json` 的 `canvas`：竖屏 `1080×1920`，横屏 `1920×1080`，方形 `1080×1080`。改完要重跑 `build`。

## 哪些是系统做的，哪些是你做的

| 环节 | 系统 | 你 |
|---|---|---|
| 身份定位 | 校验必填项，拦住"年轻人"这种空话 | **全部判断** |
| 情报采集 | 抓源、去重、合并多源、存库 | 提供源清单 |
| 选题排序 | 五项客观特征打分 + 给理由 | — |
| 选题判断 | 落成选题卡骨架 | **填四栏、下结论** |
| 脚本 | 二次分析、出结构 | 念出来、改口语 |
| 拍摄 | — | **全部** |
| 转写 | 全部 | — |
| 洗音轨 | 全部 | — |
| 切点 | 出表 + 标理由 | **复核误删** |
| 铺画面 | 全部 | — |
| 跳切掩盖 | 自动换机位 + 列待补 | 补 B-roll |
| 精剪 | 给 SOP | **全部** |
| 发布稿 | 四平台成稿 + 检查表 | **点发布** |
| 数据 | 记录模板 | 填数字 |

一句话：**系统负责"算"，你负责"判断"和"点击"。**
